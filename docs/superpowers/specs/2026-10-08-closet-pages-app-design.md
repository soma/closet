# Closet explorer: data refresh and Pages app

## Goal
1. Refresh the dataset with Criterion Closet visits newer than what `index.html` embeds.
2. Ship the explorer as a claude.ai Pages app (staged for human publish), while keeping the repo as the source of truth.

## Findings so far
- `index.html` is one 936 KB file: CSS, JS, and the dataset as a gzip+base64 JSON blob (`DATA_B64`) with tables `visits` (443), `picks` (6661), `films` (1466) in columnar form (`cols`, `rows`) plus `_meta`.
- Latest embedded visit date: 2026-01-12. Source was `letterboxd.com/closetpicks` lists. The repo contains no scraper.
- Letterboxd (`/closetpicks/lists/`, 43 index pages) and criterion.com now answer every automated request with HTTP 403, and Letterboxd's robots.txt disallows AI crawlers. **We will not work around this.** No automated refresh from either site is possible in this session.

## Decisions
### Data refresh (blocked on a sanctioned source)
- Add `scripts/merge_data.py`: takes new-visit input in the same columnar schema (or CSV files for visits/picks/films), validates it (unique slugs, every pick references a known film and visit, `pick_order` contiguous, `num_films` equals pick count), merges into the existing dataset idempotently (existing rows win unless `--overwrite`), validates the complete merged dataset, and only then saves it to `data/closet.json`, the canonical copy. The merge never touches HTML; `scripts/build.py` regenerates both HTML artifacts (`dist/index.html` and root `index.html`) from the JSON.
- The user supplies new data from an allowed route (Letterboxd export, API access, or hand-entered CSV). Until then the dataset stays at 443 visits and the report says so.
- Existing rows are never altered silently: the script prints counts added/skipped per table.

### Build
- Split `index.html` into `src/template.html` (everything except the blob, with a `__DATA_B64__` placeholder) and `data/closet.json` (decoded dataset, diff-friendly). `scripts/build.py` writes `dist/index.html` byte-compatible in behaviour with today's file. Root `index.html` stays as the GitHub Pages artifact, regenerated by the build.
- Verification: a merge-then-build regression test (merge a fixture, build, decode the built blob: the merged rows are present; merge the same fixture again: no change), a round-trip test that decoding the blob of the built file equals `data/closet.json`, and a headless-browser smoke test (Playwright) that the page boots, logs the expected counts, and all three views render.

### Pages app
- Create a Pages page "Criterion Closet Explorer" private to the creator (`grants: []`) and stage only `index.html` (no server.js, no shared data; the app has no write path).
- Known risk: Pages runs in a sandboxed iframe with a locked CSP. Google Fonts and Letterboxd poster images may be blocked. The CSS already has serif/mono fallbacks; posters already have an `err` state. We cannot check the CSP from here, so the staged preview must be opened by a human, then `read_page_events` is checked. If posters are blocked, a follow-up decides between dropping them or bundling them as assets (not decided now).
- Staging never publishes; a human publishes.

## Out of scope
Rewriting the UI, adding features, scraping, or publishing.

## Testing
Entry point is `script/test`, which runs everything below. `python3 -m unittest` for merge/validation (fixtures with duplicate slugs, orphan picks, bad counts), plus the build round-trip and browser smoke test.
